# Evidence pages — what they are, where they live, when they must be rebuilt

Decided by T, 2026-10-02. Served from the marketing site, **tikpema.xyz/evidence/…**. They are not served
from the app.

| Page | What it is | Built by |
|---|---|---|
| `/evidence/xylo-testnet/` | A **signed** due-diligence report (XyloVault family, Arc testnet), rendered sentence by sentence from the report's fields, with the report's JSON beside it | `npm run evidence:build-report -- <signed-report.json>` |
| `/evidence/galaxy-usdc-route-removal/` | A **dated on-chain record** (Arc mainnet), **not** a report. Every statement is a public read made on two endpoints that had to agree | `npm run evidence:build-galaxy` |

A stranger checks a downloaded report with `npm run evidence:verify-report -- report.json`. Exit codes:
0 = valid, 1 = not valid, 2 = could not tell.

## Where they live, and why there

- **Source:** `site/evidence/**`, generated by `scripts/public-pages/`. Never hand-edit a page.
- **Published by:** `npm run deploy:site:prod`, which needs a terminal and a typed confirmation.
  - It publishes `siteFiles()` (`scripts/lib/marketing-site.mjs`): `site/index.html` plus everything
    under `site/evidence/`.
  - `gate:sitelive` checks the same list. For each file it compares the served bytes and the bytes the
    published deploy holds, and says which way any difference runs.
- **Not on the app.** Files in `public/` ship with every app deploy. Piece-5 C, which arms operator
  deposits, must carry nothing optional.
- **A push does not publish.** Checked 2026-10-02: the tikpema.xyz Netlify site has no repo linked (no
  repo URL, no GitHub installation, no deploy key), all 24 of its deploys are CLI uploads with no commit
  ref, and the repo has no `.github` workflows. If anyone ever links the site to the repo, this rule
  changes and must be re-decided.

## Staleness

- **(a) Built in.** Each page prints its block's date at the top; that line needs no JavaScript.
  - The viewer's browser adds the age ("N days old by this device's clock").
  - From **`STALE_AFTER_DAYS` = 7** days on, a banner says the page describes that block, not today.
  - The data never refreshes itself.
  - The Galaxy page ages its "now" section only. The removal itself is history and does not age.
- **(c) The rule: rebuild, and redeploy, when any of these happens.**
  1. The page is **≥ 7 days old**. The banner is already showing to readers.
  2. **xylo's facts change:** the mandate's `owner-changed` rule fires, any receipt carries a finding,
     or the vault's code changes.
  3. **The V2 window deploys.** The renderer refuses schema 0.4.0 (it only knows 0.3.0), so the renderer
     must learn 0.4.0 before the page can be rebuilt. That is deliberate: it refuses to drop fields it
     doesn't know.
  4. **The identity behind the signature changes.** If agent 851891's owner, or that account's key,
     changes, ERC-1271 validity is "valid now", so the page's "checked valid when built" line can turn
     false. Rebuild, or take the page down.
  5. **`evidence:build-galaxy` refuses.** A fact on the page no longer holds (for example, the route was
     restored). The refusal is the signal; do not force a build.
  6. **The signed source disappears.** A fresh xylo report comes from the operator mandate's hourly
     check (read-only from its receipt). After the mandate stops (E, or a cancel), a fresh report needs
     the paid endpoint (0.06 USDC, run by T) or the logged-in in-app route.
- **(d) Later: enforce (c) with a monitor** in the `dd-watch` pattern. It will fetch the served pages,
  alert when one is 7 days old or more, re-verify the published `report.json`, and re-run the Galaxy fact
  assertions. Not built.
- **Not (b).** No automatic rebuild for each new signed report. It would mean an hourly redeploy with
  operator credentials in automation, or a public read path into the mandate's receipt store.

## What a deploy also publishes

`deploy:site:prod` publishes the whole manifest from the working tree. On 2026-10-02 the repo's
`site/index.html` was **ahead of the live page** by one claim: "15 named refusal reasons" became "17"
(commits a300359 and 04cac3b). `test:siteclaims` covers that claim, and the first evidence deploy will
publish it too.
